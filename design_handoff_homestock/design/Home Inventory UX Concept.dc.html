A home inventory organised by where things live.

Homestock is a self-hosted app for a household of 2–6 people. Every screen answers three questions: where is it, how many are left, and who has it. Mobile is tuned for capture while standing in front of a box; desktop is tuned for reviewing and reorganising. All screens below are live instances of the clickable prototype, rendered with the real tokens — the theme button switches the whole page.

Principles

Location is context, not a field
Whatever box you are looking at becomes the default for every create action. Quick add shows it as a locked bar; changing it is one deliberate tap.
Quantity is split, never duplicated
An item record owns a count. Check-outs are claims against that count (available = total − checked out). Moving part of a stack splits the record; moving to a box with the same item merges it.
Every action has a short undo path
Session rows in Quick add have Undo; check-outs have Return; used-up items stay visible at quantity 0 until restocked.
Same model, two postures
Mobile: bottom tabs with a central + and sheets from the bottom. Desktop: persistent sidebar tree that doubles as a drop zone, side panel for detail.

Core screens

Every frame is the working prototype — click around inside them. Desktop frames are 1120 × 720; phone frames are 390 × 800.

3.1 Location & container view

3a · Sectioned. Boxes as a compact list of cards above a photo grid of items. Easiest to scan when boxes hold many sub-boxes.
3b · Unified grid. Boxes are tinted tiles with a big item count, mixed into the item grid; header carries the box photo. Better for shallow boxes with few children.
3aOption A — SectionedShelf A on desktop · Storage Box 12 on mobile
Breadcrumb scrolls horizontally on mobile; current segment is a filled pill. Every segment accepts drops on desktop.
This level / Include nested — nested shows each item’s relative path (“in Cupboard › Storage Box 12”). Right frame: Office with nested on.
Zero loose items at a level with children shows a one-tap link to the nested view instead of an empty grid.
Photo thumbnails are striped placeholders until a capture exists.
3bOption B — Unified gridShelf A on desktop · Bin 3 on mobile
Box photo sits in the header; tapping it opens the camera. Useful for “what does Bin 3 look like”.
Tile count (e.g. 3 items) is recursive, so you can see how full a box is before opening it.
Trade-off: more vertical space per box; on deep trees A is denser.

3.2 Quick-add

3c · Sheet form. Full form with labelled fields, unit and a session list under the form. Desktop: right-hand drawer, so the grid stays visible.
3d · Rapid line. A chat-style composer pinned above the keyboard: camera · name · qty · ↵. Tags apply to every item. Fewest taps per item.

3dOption B — Rapid line
Locked context is the accent bar. “Change” swaps the form for a location tree; picking one re-locks and restarts the session list.
Enter saves and refocuses the name field, so the keyboard never drops. enterkeyhint labels the key “next”/“send”.
Camera is a real <input type=file accept=image/* capture=environment> wrapped in a 96 px (A) / 52 px (B) label.
Undo on each session row deletes that item immediately.

3.4 Used up & shopping list

Mark used up · flag for replacement
Shopping list · to buy
Share list · fallback sheet
Bought · put away to restock
Low stock · add to list
Used-up items · add to list
Lifecycle: Used up lowers the count (to 0 keeps the record, badged “Used up”) → To buy → tick → Bought → “Put away in Bin 4” adds the bought quantity back to the original item and clears the entry. Free-text entries (not linked to an item) open a location picker.
Share list exists because the server is only reachable on the home network. It sends the To buy items as plain text (“☐ AA batteries — 3 pcs”) through navigator.share(), which opens the phone’s own share sheet (Signal, WhatsApp, Mail, Notes…). Browsers without Web Share (most desktop, or plain-HTTP origins) get the fallback sheet: preview, Email (mailto:) and Copy text.

3.5 Sign-in, account & user admin

Sign-in is household-style: tap your name, enter your password. There is no self-service reset because the app is self-hosted with no email; an admin issues a temporary password and the person must change it at next sign-in. Members can browse, add and check out; admins can also manage users. Demo password in the prototype: homestock.

Switch layouts on container width, not user agent. Moving is drag-and-drop on pointer devices (≥ 640) and the Move… sheet everywhere — touch never relies on drag.

Touch targets

44 × 44 minimum for every control; icon buttons get the full 44 even if the glyph is 16.
Steppers: 52–56 px square buttons with 64 px value well; long-press repeats after 400 ms at 10/s. Dialog steppers offer an “All N” shortcut.
Camera: 96 px (sheet form) or 52 px (rapid line) label wrapping a visually-hidden file input — never display:none, which breaks focus.
Primary sheet action: 56 px tall, full width, pinned above the safe-area inset.
Checkbox rows: 48 px hit area around a 24 px box.
Spacing: ≥ 8 px between adjacent targets.

Drag & drop rules

Sources: box cards (move box + all descendants) and item cards (move whole record).
Targets: box cards, breadcrumb segments, sidebar tree rows, empty-box drop zone.
Invalid: a box into itself or any descendant, or into its current parent — no highlight, no drop.
Feedback: source at 40 % opacity; target gets 2 px accent ring + accent-soft fill + “Drop into …” label.
Result: toast with what moved and how many items came along.
Partial moves use the Move… sheet (quantity stepper); checked-out units stay behind.

Data model

          password_hash, must_change_pw

available = item.qty − Σ checkout.qty
low       = qty > 0 and available ≤ min_qty
used up   = qty = 0

Auth & roles

Session: HttpOnly, SameSite=Lax cookie, 30-day sliding expiry; argon2id password hashes.
First run: no users yet → setup screen creates the first admin (same layout as Sign in, one name + password).
Wrong password: inline error under the field, field cleared; rate-limit after 5 tries per minute.
Reset by admin: generates a 3-word temporary password, revokes that user’s sessions, sets must_change_pw.
Guards: can’t remove the last admin or yourself; can’t remove someone with items checked out.
Members see Household read-only; admin buttons are not rendered (and the API rejects them).

UI states

Empty box
Search loading (skeleton)
Fuzzy results · “batery”
Empty box — dashed drop zone, name in the headline, two actions (Quick add, Add box inside). Never a blank grid.
Search loading — debounce 300 ms; show 4 skeleton rows matching the result row geometry; keep previous results if a new query takes > 1 s.
No results — echo the query, suggest a shorter word or tag; chip filters stay visible so they can be removed.
Grid loading — skeleton cards at the real aspect ratio (4:3 photo + two lines); breadcrumb renders immediately from cache.
Optimistic writes — create/move/check-out apply instantly; on server error revert and show a toast with Retry.
Photo upload — local object-URL preview at once; upload in the background, resized to 1600 px long edge before sending.
Disabled — 45 % opacity plus disabled; Check out is disabled when available = 0.
Web Share — needs a secure context: serve over HTTPS on the LAN (e.g. Caddy with a local CA) or phones won’t show the share sheet; the fallback still works.
Theme — data-theme on <html>, saved to localStorage, defaults to prefers-color-scheme.
